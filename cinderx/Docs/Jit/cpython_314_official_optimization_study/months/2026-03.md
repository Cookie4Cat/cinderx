# 2026-03 官方优化

3 月的主线是把 CPython 3.14 specialization 真正变成 JIT 里的 typed fast path。

## 重点 commits

- `5fec65f4` Enable specialized opcode support by default
- `8635acf5` Replace unlink frame generation with LIR generated version
- `d70dcb5a` Unbox float TrueDivide and mixed float/int ops to DoubleBinaryOp
- `e9968ea2` Fuse compare + CondBranch into cmp + jcc
- `54cb7a83` Specialize list StoreSubscr to skip PyObject_SetItem dispatch
- `44e26d22` Inline StoreArrayItem LIR lowering to a direct memory store
- `d5fa88c3` Don't generate Decrefs for immortal types

## 阅读重点

### Specialized opcode 默认开启

`5fec65f4` 是 3.14 接入的关键节点。它改变了 CinderX 对 CPython adaptive interpreter 的态度：不再只把 quickened opcode 当成解释器内部细节，而是把它作为 JIT type information source。

### Numeric unbox

`d70dcb5a` 是很好的 deep review 模板。它展示了如何把 mixed `float/int` 和 `TrueDivide` 这种动态语义，收窄成 `DoubleBinaryOp` 之类 primitive path。

### Container fast path

`54cb7a83` 和 `44e26d22` 应该连着读：前者在 HIR 层跳过 generic dispatch，后者继续把 LIR lowering 变成 direct memory store。这类优化收益可能很直接，但 correctness fallback 和异常语义也最容易出问题。

### Compare + branch 融合

`e9968ea2` 展示了一个经典 codegen 思路：不是所有优化都发生在高级语义层。把 `Compare` + `CondBranch` 调整成机器指令自然支持的 `cmp + jcc`，能减少中间值和寄存器压力。

## 可复用方法

- 每次只保留一个 specialized opcode family。
- HIR builder 负责 guard / typed lowering。
- simplify 负责 unbox / fold。
- LIR/codegen 负责别把高级层收益重新浪费掉。
