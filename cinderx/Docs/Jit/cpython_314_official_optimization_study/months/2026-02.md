# 2026-02 官方优化

2 月的主线是铺底座：frame、LIR opcode、AArch64 backend、benchmark 都在为 3/4 月更激进的 specialization 做准备。

## 阅读重点

### Frame 和 runtime overhead

`5bfab630`、`659606ab` 的重点不是单个 Python benchmark 立刻大幅变快，而是降低 JIT frame/trampoline 的基础成本。官方思路是把原来偏 runtime/assembly 的行为逐步变成 LIR instruction，让后续统一优化。

### LIR opcode 明确化

`8b98266a` 把 load/store size 显式放进 opcode，是一种很工程化的优化：让后端少猜，减少 lowering 时的特殊分支。

### AArch64 bring-up

`d37552a7` 属于 correctness bring-up，不应直接拿它和性能优化混在一起看。ARM64 优化通常分两步：先让 backend 正确，再做 branch/call/immediate/register pressure 质量优化。

### Benchmark 先行

`6e5e3716` 增加 `nbody`、`binary-trees`、`spectral-norm`，说明官方不是只靠 microbenchmark。numeric、allocation、loop-heavy workload 都要覆盖，后续 HIR simplify 才有验收对象。

## 可复用方法

- 先扩 benchmark，再做优化。
- 把隐式 runtime 行为转成显式 IR instruction。
- backend bring-up 和 backend performance 要分开评估。
